# 06 - 模块设计：GEO 审计引擎（Python）

## 引擎架构

```
server.py (stdio 入口)
    │
    ├── 解析输入 JSON
    │
    ├── scorer.py (主评分器)
    │   ├── citation_density.py    引用密度
    │   ├── claim_clarity.py       命题清晰度
    │   ├── structure_parse.py     结构可解析性
    │   ├── authority_signal.py    权威信号
    │   ├── fact_verifiability.py  事实可核验性
    │   └── platform_fit.py        平台适配度
    │
    ├── suggester.py (建议生成器)
    │   └── 根据 issues 生成可执行 fix
    │
    └── 输出 JSON 结果
```

## 6 个评分维度实现

### 1. 引用密度 (citation_density)
- 检查：数据来源标注、参考文献、标准编号引用
- 规则：每 500 字至少 1 个引用标记
- 权重：20%

### 2. 命题清晰度 (claim_clarity)
- 检查：首段是否有定义句、结论是否明确
- 规则：匹配"[主题] 是 [类别] 的 [定义]"模式
- 权重：15%

### 3. 结构可解析性 (structure_parse)
- 检查：H2/H3 层级、列表使用、表格存在、段落长度
- 规则：H2 不超过 6 个，段落不超过 150 字，必须有列表或表格
- 权重：20%

### 4. 权威信号 (authority_signal)
- 检查：标准编号（ISO XXXX）、机构名称、年份、官方链接
- 规则：至少引用 1 个标准编号或官方机构
- 权重：15%

### 5. 事实可核验性 (fact_verifiability)
- 检查：数字、百分比、日期、费用范围
- 规则：每篇至少 3 个可验证数据点
- 权重：15%

### 6. 平台适配度 (platform_fit)
- 检查：FAQ 结构、列表密度、段落长度、标题格式
- ChatGPT 偏好：短段落 + 列表 + FAQ
- Kimi 偏好：表格 + 数据摘要
- 百度 AI 偏好：权威引用 + 结构化
- 权重：15%

## 建议生成规则
每条 issue 必须包含：
- `id`: 编号（GEO-XXX）
- `severity`: high / medium / low
- `title`: 一句话描述问题
- `evidence`: 从原文中提取的证据
- `fix`: 具体可执行的修复文案（可直接复制使用）
